# CLAUDE.md

Guidance for Claude Code when working in this repository.

Note: a parent `CLAUDE.md` at `../CLAUDE.md` describes an unrelated Open edX plugin
sample repo. None of it applies here.

## What this project is

`pyqti` is an early Python implementation of the QTI 3.0 assessment standard. It
parses `qti-assessment-item` XML, grades responses with a real response-processing
interpreter, and publishes a redacted, presentation-safe copy of an item for a
browser to render. `README.md` is the authoritative prose on approach and status;
`TODO.md` records known gaps. Prefer updating those over duplicating them here.

## pyqti.models is auto-generated and enormous — never read it whole

`src/pyqti/models/` is ~118,000 lines across ~640 files, generated by
[`xsdata`](https://xsdata.readthedocs.io/) from 1EdTech's QTI 3.0 XSD set (plus the
W3C schemas it references, including MathML).

**Rules when working with it:**

- **Never read a models file in full, and never dump the package into context.** Some
  single files are huge: `cerror.py` is ~54k lines, `adtype.py` ~14k,
  `any_ndtype.py` ~11k. Read only the slice you need — `grep -n` for the class or
  field first, then `sed -n 'START,ENDp'` around the hit. Read a few dozen lines at a
  time, not a few thousand.
- **Never hand-edit these files.** They are regenerated wholesale. The generation
  command is in `README.md`; `--compound-fields` is load-bearing (without it field
  names change and `qtitree.py` breaks), and the recorded invocation predates the
  `src/` layout, so its output path needs adjusting before the next regeneration.
- Linting and type checking already skip the package (`extend-exclude` in
  `[tool.ruff]`, `exclude` plus a `pyqti.models.*` override in `[tool.mypy]`). Keep it
  that way.
- Importing `pyqti.models` costs tens of MB of resident memory, which is why
  `pyqti/__init__.py` resolves its exports lazily (PEP 562). Don't add eager
  top-level imports of the models to `__init__.py`. `uv run overhead` measures this.

## This repo does not implement QTI rendering

**pyqti has no front end and is not meant to grow one.** Presentation is delegated to
existing QTI web components in the browser — currently
[Citolab `@citolab/qti-components`](https://github.com/Citolab/qti-components), loaded
from a CDN — which consume QTI XML directly. Do not add an HTML/React/template
renderer, a QTI-to-HTML transform, or a presentation vocabulary implementation.

The only front-end code here is the demo harness under `src/pyqti/demo/`, and it is
deliberately thin: `static/qti.js` is glue that moves candidate responses from the web
components to pyqti's grading endpoint. It contains no rendering and no scoring, and
it must never invoke the renderer's own response-processing entry point. If a task
sounds like "make it look like X", the answer is almost always a change to the served
XML or to the components' configuration, not new rendering code.

The server's job on the presentation side is redaction: the authored item contains the
answer, so `presentation_xml()` in `pyqti/redaction.py` is the **only** function
permitted to produce item XML for a front end.

## Layout

- `src/pyqti/loading.py` — strict parsing of `qti-assessment-item`.
- `src/pyqti/item.py` — the domain view (`ItemDefinition`, declarations, interactions).
- `src/pyqti/session.py` — `ItemSession`, variable initialisation, grading.
- `src/pyqti/processing/` — response-processing AST, compiler, evaluator, and vendored
  built-in templates (`match_correct.xml`, `map_response.xml`).
- `src/pyqti/redaction.py` — allowlist redaction; element, attribute and field level.
- `src/pyqti/serialization.py` — models back to QTI XML.
- `src/pyqti/qtitree.py`, `src/pyqti/_xsdata.py` — **all** contact with xsdata lives
  here. Several APIs used are not xsdata's documented public surface, which is why
  `pyproject.toml` pins `xsdata<27`. `tests/test_qtitree.py` asserts those structural
  assumptions so a bump fails loudly.
- `src/pyqti/values.py` — normalises the several generated `base-type` / `cardinality`
  enums; nothing should compare the generated enums directly.
- `src/pyqti/demo/` — stdlib HTTP harness (`qti-demo`); JSON contract documented in
  `server.py`'s module docstring.
- `src/pyqti/xblock/` — the **optional** Open edX integration, behind the `xblock`
  extra. Nothing in core imports it, and nothing in it belongs in `_EXPORTS`. It
  registers the OLX tag `qti-assessment-item`, so the block's OLX root *is* the QTI
  element.
- `tutor_plugin/` — a separate distribution (`tutor-contrib-pyqti`): a Tutor plugin
  for `tutor dev`. It installs into Tutor's virtualenv, not the Open edX image, so its
  `requires-python` follows Tutor (`>=3.10`), not this project.
- `examples/` — fixtures, including `adversarial-leaks.xml`, which carries a unique
  sentinel per known leak vector.

## Commands

```sh
uv run pytest                                   # full suite
uv run pytest tests/test_redaction.py::test_x   # one test
uv run ruff check
uv run mypy
uv run qti-demo                                 # http://127.0.0.1:8000/
uv run overhead                                 # model import/parse memory + timing
```

The `xblock` extra is optional and must stay that way: `tests/xblock/` skips cleanly
when it is absent (`tests/xblock/conftest.py` uses `importorskip`), and
`tests/test_optional_xblock.py` asserts that a bare `import pyqti` never pulls in the
framework. Check both configurations before claiming the suite is green.

## Conventions

- Python 3.13+, `uv` for everything. Line length 88; ruff rules `E,F,I,UP,B`.
- **Fail loudly.** Anything QTI defines that pyqti does not implement must raise a
  subclass of `UnsupportedQtiFeature`, never be silently ignored. Silently dropping
  content mis-grades candidates and looks like success.
- **Redaction is allowlist-only.** New fields on `QtiAssessmentItem` must be explicitly
  classified in `redaction.py`; an unclassified field raises, and that is intentional.
  Test redaction over `(element, attribute)` pairs — element names alone miss the
  attribute leaks that `tests/test_redaction.py` exists to catch.
- Security-relevant changes to redaction or delivery should be reflected in `TODO.md`
  if they close (or open) a gap listed there.
- **lxml is a required dependency and must stay one.** xsdata picks its parser handler
  and serializer writer from whether lxml is importable, and the two pairs disagree
  about mixed content. Making lxml optional again would make `presentation_xml` output
  vary with the environment — and that output is a security boundary tests assert over
  as text. `tests/test_serialization.py::test_xsdata_uses_the_lxml_backed_pair` guards
  this.
